# Предсказание движения и проверка выстрела

Группа ИКБО-32-23: Мызников Роман Владиленович, Карамышева Виктория Сергеевна, Мелива Сергей Важаевич.

Unity 6000.5.10f1, Netcode for GameObjects 2.13.3. В задании механизмы названы классами Unreal. Здесь у каждого есть прямой аналог, без WheelCollider: физика колёс не детерминирована, и повтор команд после сверки с сервером разъехался бы.

## Соответствие

| В задании | В этой игре |
| --- | --- |
| Listen server | `NetworkManager.StartHost`: тот же процесс и сервер, и игрок |
| Server authority | Позу пишет только сервер в `CarAvatar.ServerState` |
| Autonomous proxy | `IsOwner`: локальная машина, с неё уходит ввод |
| Simulated proxy | Чужая машина. Рисуется серверная поза, ввод с неё не читается |
| CharacterMovementComponent | `CarSim.Apply` / `CarSim.Integrate`. Один и тот же код на клиенте и на сервере |
| Saved move | Список `pending`: команды, на которые сервер ещё не ответил |
| ServerMove | `SubmitDriveRpc`: номер такта, газ, руль, флаг выстрела. Координат в пакете нет |
| Client-side prediction | Сразу после команды клиент вызывает `CarSim.Apply`, если предсказание включено |
| Server reconciliation | Сервер присылает позу и номер принятого такта. Клиент выбрасывает команды до этого номера и заново прогоняет остальные |
| Сглаживание | Чужая машина догоняет позу интерполяцией. Своя при ошибке больше 1.2 м встаёт сразу, меньшую ошибку догоняет |
| NetEmulation.PktLag / PktLoss | Поля «задержка в одну сторону» и «потери» в `NetEmulation`. Кнопки 0 мс, 100 мс, 180 мс и 4% |
| Проверка действия | Выстрел. Повтор, пока `cooldown` больше нуля, сервер не принимает |

## Почему сервер не записывает присланную позицию

Клиент может прибавить к своей машине что угодно. F2 так и делает: локальный `x` увеличивается на 8, на сервер это не отправляется. Сервер по-прежнему интегрирует только газ и руль. Когда приходит его поза, клиент подставляет её и заново применяет неподтверждённые команды. Лишний сдвиг в этих командах отсутствует, поэтому машина возвращается.

То же с выстрелом. `DriveInput.fire` — это просьба. `CarSim.Apply` ставит кулдаун только если он уже дошёл до нуля и у машины ещё есть блоки. F3 обнуляет кулдаун лишь в локальной копии и всё равно шлёт просьбу. Серверная копия просьбу отклоняет, следом клиент получает прежний кулдаун.

Позиция клиента нигде не читается как источник истины. В `DriveInput` есть только `tick`, `throttle`, `steer`, `turret`, `fire`.

## Шаг симуляции

Такт 1/30 с, тот же `Time.fixedDeltaTime`. За такт:

- газ прибавляет скорость, тормоз уменьшает, без педалей скорость гаснет;
- руль поворачивает тем сильнее, чем больше скорость. Задним ходом знак руля меняется;
- позиция — это скорость вдоль рысканья. За границей арены скорость обнуляется;
- кулдаун уменьшается на длину такта;
- скорость зависит от мощности, массы и доли живых колёс на осях. Нет мощности или хода — машина не едет.

Выстрел — отдельное решение после шага. Попадание считается на сервере лучом по вокселям. Один удар снимает одну единицу прочности клетки. Маска блоков приходит в той же позе. Клиент при повторе команд маску не выдумывает: после повтора подставляет серверную.

Движение уходит ненадёжным RPC: потерянный такт просто не будет в повторном прогоне, и машина чуть короче проедет. Выстрел дополнительно уходит надёжным RPC с номером такта. Если пакет движения потерялся, сервер всё равно может засчитать выстрел на ближайшем следующем принятом такте, но снова только при нулевом кулдауне.

## Эмуляция сети

На клиенте исходящая команда ждёт `OneWayLagMs` и с шансом `LossPercent` не отправляется. Входящая поза ждёт столько же и так же может быть отброшена. Хост свои команды не задерживает: он и есть сервер, отдельной сети между ними нет. Для записи задержки нужно окно клиента.

Без предсказания рисуется только последняя принятая поза, поэтому запаздывание примерно равно двум односторонним задержкам. С предсказанием локальная машина реагирует в том же такте, а список `pending` показывает, сколько команд ещё не подтверждено.

## Что сознательно не является предметом оценки

Разрушение кузова — игровое следствие попадания, а не механизм из задания. Оценке подлежат отказ сервера в повторном выстреле и возврат машины к серверной позе.
